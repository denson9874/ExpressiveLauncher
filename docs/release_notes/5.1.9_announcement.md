# Expressive Launcher 5.1.9 QA (Build 82) — Don't Recycle What's Still on Screen

5.1.9 fixes a Recents crash introduced in 5.1.8 (81) where Overview cards could throw `Canvas: trying to use a recycled bitmap` after Android 17 delivered an updated task snapshot.

---

### ✨ What's New & Improved

#### 1. 🛠️ Fix Recents recycled-bitmap crash (5.1.8 regression)
- **Before**: in 5.1.8 (81), `RecentsModel.onTaskSnapshotChanged()` stopped unconditionally reporting snapshots as consumed, while `TaskVisualsChangedDelegateImpl` (and `RecentsView` on the legacy path) still returned `null` after handing the incoming `ThumbnailData` to `TasksRepository`. Whenever Android 17 delivered an updated snapshot for a visible Recents card that was not currently in the 3-slot `TaskThumbnailCache` (for example after LRU eviction, memory trim, or `lastActiveTime` invalidation), `TaskStackChangeListeners` immediately recycled the live `Bitmap` right before `TaskThumbnailView`'s `FixedSizeImageView` drew it—crashing the launcher with `Canvas: trying to use a recycled bitmap`.
- **Now**: `TaskVisualsChangeListener`, `TaskVisualsChangedDelegateImpl`, `TasksRepository`, and `RecentsView` accurately report `true` whenever they retain a task snapshot, so live Recents card bitmaps are never prematurely recycled, while genuinely unused snapshots are still freed immediately.

#### 2. 🛡️ Defense-in-depth guards for Recents thumbnails
- **Before**: `TaskUiStateMapper`, `TaskThumbnailView`, `TaskThumbnailCache`, and `TaskThumbnailViewDeprecated` only checked for `null` bitmaps without checking `isRecycled`, and `TaskThumbnailView.resetViews()` cleared its `ImageView` with `setImageBitmap(null)` (which still leaves an empty `BitmapDrawable`).
- **Now**: all four layers guard against recycled bitmaps (falling back cleanly to the task's background color or a cache miss), and `TaskThumbnailView.resetViews()` clears its drawable with `setImageDrawable(null)`.
