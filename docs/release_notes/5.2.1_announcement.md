# Expressive Launcher 5.2.1 QA (Build 84) — System Accent & ExpressiveOS Palette Fix

5.2.1 fixes a `5.2.0` regression where setting **Accent color** to **System** on Android 12+ / ExpressiveOS ignored the system color seed and rendered a hardcoded mint-green/burgundy palette across the App Drawer, themed icons, search bar, and Settings.

---

### ✨ What's New & Improved

#### 1. 🎨 Restore System Accent & ExpressiveOS Monet Palette Tracking (`5.2.0` regression)
- **Before**: `5.2.0` switched the `expressive` flavor's default `color_style` to `expressive`, exposing a latent cache-key mismatch in `ThemeProvider` where `SystemColorScheme` was only stored at `Pair(0, Style.TONAL_SPOT)`. On Android 12+ with `Accent color = System`, `getColorScheme(0, Style.EXPRESSIVE)` missed the cache and constructed `MonetColorSchemeCompat(0, Style.EXPRESSIVE)`, where `0` (`Color.TRANSPARENT`) fell back to hardcoded `GOOGLE_BLUE` (`#1B6EF3`) rotated by `Style.EXPRESSIVE`—causing mint-green accents and burgundy themed-icon circles instead of the OS/eOS system palette.
- **Now**: `ThemeProvider` caches `SystemColorScheme(context)` in a dedicated `systemOverlayColorScheme` field on Android 12+ (`Utilities.ATLEAST_S`) and returns it for `ColorOption.SystemAccent` regardless of `colorStyle`, so App Drawer, themed icons, search bar, widgets, and Settings match the system/eOS palette directly.

#### 2. 🔄 Live System Overlay Refresh & Non-System Color Style Preservation
- **Before**: `overlayChangedReceiver` only refreshed `colorSchemeMap[Pair(0, Style.TONAL_SPOT)]`, so system theme/wallpaper changes never invalidated non-`TONAL_SPOT` entries, and users who previously tried a custom color style and returned to **System** remained stuck on the broken fallback.
- **Now**: `android.intent.action.OVERLAY_CHANGED` (for `package:android`) always refreshes `systemOverlayColorScheme` and notifies listeners; **Custom** and **Wallpaper** accent modes continue to default to M3 Expressive (`Style.EXPRESSIVE`) and respect user-selected color styles.

#### 3. ✅ OTA Cleanup Race Fix, Regression Coverage & GitHub Issue Closure
- Fixed a race in `NightlyBuildsRepository.installUpdate()` so invalid downloaded APKs are deleted before emitting `UpdateState.Failed`.
- Added `ThemeProviderSystemPaletteTest` covering real `ThemeProvider` resolution (no `ShadowThemeProvider`) across SDK 36 and SDK 37 for default `SystemAccent` + `Expressive`, all `ColorStyle` values, `OVERLAY_CHANGED` refresh, and `CustomColor` → `SystemAccent` switching.
- Audited and closed shipped GitHub feature requests `#73` (custom icons from images) and `#74` (hide app badge on shortcuts), both shipped since `5.1.7 (80)`.
