# Expressive Pro free trial — Implementation Plan

**Goal:** Let Free users try every Pro feature for a limited time (TG-008), then return to Free Core
cleanly, with one trial per device. Target: 4.1.x.

**Architecture:** A trial is an ordinary signed Pro license, so no second unlock path is needed. The
existing license format already carries `expiresAt` (ECDSA P-256, verified offline by
`ProLicenseVerifier`, which rejects expired keys) and device binding (`recipient = device:<id>`). The
activation worker issues a short-lived, device-bound key of a new type `TRIAL`, records that the device
used its trial, and the app activates it through the existing `ProManager.activate` path.

## Decisions (user, 2026-10-05)

1. **Length: 7 days.**
2. **One trial per device, keyed on a hashed Android ID** (SHA-256 of SSAID + package; it survives
   reinstall and data clear for the same signing key and user, and the raw ID never leaves the phone).
   Requires the privacy policy update below.
3. All Pro features during the trial (`features = 0xFFFFFFFF`).

## Design

**Server (`server/cloudflare-worker/worker.js`)**
- `POST /api/trial` with `{ device_id, trial_fingerprint }`. `trial_fingerprint` = SHA-256 of
  (SSAID + package name), computed on device; the raw Android ID never leaves the phone.
- KV key `trial:fp:<fingerprint>`. If it is absent: sign
  `generateProLicense("device:<device_id>", TYPE_TRIAL, now + N days)`, store it with its expiry, and
  return it. If it is present: return the stored key (re-delivery after a reinstall), or HTTP 409
  `trial_used` once expired.
- Rate limit per IP via a KV counter; reject malformed IDs; no email or other personal data.

**App (`lawnchair/src/app/lawnchair/pro/`)**
- `LicenseType.TRIAL(6, "Pro Trial")`. Older app versions map unknown ids to `TESTER`, so a trial key
  still verifies and expires correctly there.
- `ProActivationService.startTrial(deviceId, fingerprint)`, then `ProManager.activate(key)`.
- Expiry while running: `ProManager` schedules a `refreshState()` at `expiresAt` and re-checks in
  `onResume`, so Pro turns off without a restart. Clock rollback guard: persist the highest time seen;
  if the clock moves back more than 24 hours, treat a trial as expired.
- UI: "Try Pro free for 7 days" in the locked `ProGate` placeholder sheet and in the Pro banner. While
  active, show "Pro trial — N days left" and the purchase path. On expiry, show a one-time notice; Pro
  settings fall back to their locked placeholders, and user data and settings stay intact (Pro-only
  values remain saved but inactive, as with an expired tester key today).

**Policy and docs**
- `docs/PRIVACY_POLICY.md`: disclose the activation server (PayPal email lookup already stores data
  there, which the policy does not mention today) and the hashed trial fingerprint.
- Release notes: free trial, length, one per device.

## Tasks
- [ ] Worker: `TYPE_TRIAL`, `/api/trial`, KV schema, rate limit; unit tests with Miniflare or a mocked KV.
- [ ] App: `LicenseType.TRIAL`, fingerprint helper, `startTrial`, expiry scheduling and rollback guard.
- [ ] UI: trial button, days-left state, expiry notice; TalkBack labels; settings search unaffected.
- [ ] Tests: `ProTrialTest` (issue → active → expiry → Free; rollback guard; one trial per fingerprint
      via fake service), plus existing Pro UX tests.
- [ ] Privacy policy update; worker deploy (`wrangler deploy`, needs the user's Cloudflare login).
- [ ] Emulator check: start trial, Pro settings unlock, advance clock past expiry, Pro reverts and the
      trial cannot be restarted after clearing data.

## Risks
- Factory reset or another Android user profile yields a new SSAID, so a new trial is possible.
  Acceptable for a $4.99 product.
- Worker deploy and KV are production infrastructure: deploy only after tests, and keep the existing
  `/api/license` and PayPal paths unchanged.
